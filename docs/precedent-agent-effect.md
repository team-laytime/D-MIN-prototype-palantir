# 유사 사례 검색 효과 모의 검증

[로드맵](precedent-agent-roadmap.md) / [검색 기준](precedent-agent-search.md) / [화면 검증](precedent-agent-screen.md)

팀 솔버를 실행해 둔 평가 구간 4개에서 기존 태그 검색과 제약 기반 검색을 비교했다. 같은 원천을 사용했을 때 태그 검색은 적합한 사례 1건과 부적합한 사례 11건을 띄웠다. 제약 기반 검색은 적합한 6건을 띄웠고 맞는 사례가 없는 8월 10일에는 빈 결과를 반환했다.

## 평가 방법

- 개발용 구간 17개를 검색 원천으로 사용했다. 평가용 4개를 3개 항차 그룹 단위로 제외했다. 3월 1일, 3월 10일, 10월 15일, 11월 9일 시연 구간은 유효기간 72시간으로 잡았고 원천·평가 데이터의 솔버 연장 구간까지 겹침이 없는지 검사했다.
- 원래 목업은 커밋 `f0c245b`의 8개 카드와 태그 산출 함수를 사용했다. 같은 데이터 비교에서는 기존 일치 수·날짜 정렬을 그대로 쓰고 제약 기반 검색과 동일하게 미래·동일 그룹·평가 사례를 제외했다. 두 방식 모두 최대 세 건이며 같은 원천 비교에서는 그룹당 한 건만 노출했다. 태그의 메일 입력에는 미처리 상태로 생성되는 기존 시연용 메일을 적용했다.
- 적합 사례는 원본 판정과 공통 조건 재현을 읽어 질의별로 지정했다. 교대 사례는 10월 3일과 병목이 같으면서 **순서를 바꾼 사례와 비용을 고려해 배치를 유지한 사례**를 모두 포함한다. 8월 10일보다 앞선 4월 3일은 이미 상한을 넘은 보류 사례이고, 6월 23일은 하한 사례다. 9월 19일은 당시 검색 가능한 시점보다 늦었다.
- 현재 제약은 스냅숏을 화면 모델로 변환해 구했다. 12월 7일은 A 미산출로 비교 화면까지 열리지 않아 계산 상태를 직접 읽었다. 검색 실험의 선석·순서 변경 가능 여부는 확인된 상태로 고정했다. 실제 변경 권한은 미확인이다.

## 검색 결과

| 방식 | 적합한 카드 | 부적합한 카드 | 적합 사례가 있는 질의에서 발견 | 사례 없는 질의에서 빈 결과 |
|---|---:|---:|---:|---:|
| 기존 목업 태그 검색 | 0 | 12 | 0/3 | 0/1 |
| 같은 데이터에서 태그 검색 | 1 | 11 | 1/3 | 0/1 |
| 제약 기반 검색 | 6 | 0 | 3/3 | 1/1 |

목업 카드 8건은 모두 2026년 가상 사례다. 같은 데이터 비교에서는 2025년 모의 판정만 사용했다.

| 평가 구간 | 이번 핵심 제약 | 같은 데이터에서 태그 검색 | 제약 기반 검색 | 확인 사항 추가 |
|---|---|---|---|---:|
| 08-10 | 석유제품 반출 탱크 상한 80%, 여유 5.5%p, 계획 연장 구간 | 07-27, 07-07, 06-23 | 해당 없음 | 0/1 |
| 10-03 | 1-1 선석 8척 연속 접안, 교대 추가 여유 0시간 | 09-19, 08-23, **07-27** | **05-23, 07-27, 02-10** | 2/2 |
| 11-23 | 3~7번 하역 중단 기준 10·14m/s 비교 | 10-23, 09-19, 08-23 | **05-07, 03-23** | 1/1 |
| 12-07 | 기준 후보 A와 비교 후보 B 미산출, C만 산출 | 10-23, 09-19, 08-23 | **04-19** | 1/1 |

굵게 표시한 날짜가 평가 기준에 맞는 사례다. 카드 유무 양쪽에서 현재 제약 정보는 4건 모두 확보됐다. 두 조건에 동일한 현재 후보·리스크를 두고, 이번에 해야 할 조치가 명시됐는지 5개 확인 항목으로 채점했다. 카드 없이는 0/5, 카드를 더하면 4/5였다. 10월 3일에는 선행 작업 종료예정과 후속 확정 마감, 대체 선석 가용 시간과 변경 권한을 확인하라는 안내가 추가됐다. 검증 당시 8월 10일처럼 빈 결과가 나올 때는 승인 상한과 최신 입출고·재고를 확인하라는 안내도 빠졌고, 12월 7일 진단은 오프라인에서만 가능했다. 두 화면 모두 [R10에서 보강했다](precedent-agent-screen.md).

실행 시간은 네 질의를 500회 반복한 배치로 계산했다. 준비 실행 5회 후 9개 배치의 질의당 평균에서 중앙값을 냈다. Node v26.5.0에서 기존 목업 약 0.001ms, 같은 데이터 태그 약 0.008ms, 제약 기반 약 0.002ms였다. 입력 생성, 후보 계산, 파일 읽기, 화면 렌더링, 판단 시간은 측정 범위에서 제외했다.

## 후보를 결정할 때 확인할 내용

10월 3일의 팀 솔버 재현에서는 1-1 선석 선행 작업이 30% 길어지는 조건으로 각 후보를 같은 풍속 운영 기준에서 평가했다.

| 3~7번 중단 기준 | A 예상 체선료 / 후속 지연 | B 예상 체선료 / 후속 지연 | C 예상 체선료 / 후속 지연 |
|---|---:|---:|---:|
| 14m/s | $166,311.90 / 7척 | $152,380.76 / 1척 | $174,081.81 / 0척 |
| 10m/s | $169,827.28 / 7척 | $157,062.02 / 1척 | $178,763.07 / 0척 |

두 기준 모두 B는 C보다 예상 체선료가 $21,701.05 낮고 후속 1척이 14.06분 밀렸다. 해당 선박의 확정 마감에 그 지연을 흡수할 여유가 있으면 B의 비용 우위가 판단 근거가 된다. 여유가 부족할 때는 C가 그 지연을 없애는 대안이며, 후속 지연의 영향과 선석 변경 가능 여부를 확인해야 한다.

평가에 사용한 네 질의는 검색 규칙 검증에서도 사용했다. 수치는 사전 지정 구간의 재현 결과와 작성한 적합 기준에 한정된다. 운영 효과를 평가하려면 별도 구간의 실행·정산 결과와 판단 소요시간이 필요하다. 현재 데이터의 확대 우선순위는 설비 중단, 긴급 출하, 고정 접안이며, 사례 수와 함께 독립 항차 그룹 수를 확인해야 한다.

## 재실행

```bash
node tools/real-data/evaluate_precedent_effect.mjs \
  ../output/precedent-agent ../output/precedent-agent/effect-evaluation.json
```

결과 JSON에 평가 질의, 카드 날짜, 적합 근거, 확인 항목, 실행 시간과 두 풍속 기준의 A/B/C 교란 재현값을 남긴다. 실행 중 원본 스냅숏 해시, 시연 구간 겹침, 평가 그룹과 검색 원천의 분리를 검사한다.
