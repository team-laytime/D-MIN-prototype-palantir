# 요소의 존재 이유 검토

다음은 금지 목록이 아니라 수정 전후 검토 질문이다.

| 대상 | 유지할 이유 | 제거·대체할 조건 |
|---|---|---|
| 요약 지표 | 해당 화면의 다음 행동을 정한다 | 상태 탭과 같은 수치를 반복하거나 이력 화면과 무관하다 |
| 컨테이너 | 선택/검토/확인의 경계를 표현한다 | 단순한 제목·값 묶음을 모두 카드로 만든다 |
| 색 | 상태·선택·위험·초점을 구분한다 | 브랜드 색 때문에 본문 대비가 낮아진다 |
| 여백 | 비교 대상과 처리 동작을 구분한다 | 비어 있는 헤더와 최소 높이로 업무 영역을 줄인다 |
| 아이콘·아바타 | 기능이나 데이터 식별을 돕는다 | 이니셜·장식이 이미 명확한 이름을 반복한다 |
| 보조 문구 | 누락된 맥락·실패 복구를 제공한다 | 제목을 반복하거나 실제로 수행하지 않는 일을 약속한다 |
| 반응형 | 같은 업무를 작은 화면에서 완료한다 | 표 전체를 자르고 상세를 행 목록 아래 멀리 배치한다 |

각 변경은 결함 ID, 원인, 가설, 동일 조건 캡처, 기능 확인, 채택 여부와 연결한다. 색·간격만 바꾼 반복은 독립 개선 사이클로 계산하지 않는다.
