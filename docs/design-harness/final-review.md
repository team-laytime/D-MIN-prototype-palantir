# D-MIN 관리자 섹션 최종 보고

2026-11-25 · 대상 Figma [계정 관리 섹션](https://www.figma.com/design/mDE8EoyYV0dS2WjtBLUoet/SKALA-P2-1?node-id=1004-1448) · 실행 주소 `http://localhost:5175/?view=admin`

## 1. Executive Summary

기존 결과의 문제는 장식만이 아니었다. 신청/계정 화면의 서로 다른 표현, 낮은 대비, 모바일 선택과 검토의 분리, 미확인 상태의 완료 표시, 승인 집계와 감사 기록의 의미 오류가 있었다.

최종 방향은 **운영 대장 + 검토 패널**이다. 사용자 식별 직후 역할과 담당 부두·팀을 검토하고, 실제 확인 조건을 충족한 뒤 처리한다. 좁은 화면에서는 핵심 정보를 한 행에서 읽고 즉시 상세 검토를 연다. 그라데이션·반복 카드·아바타 대신 데이터 순서·정렬·상태·초점으로 위계를 만든다.

별도 디자인 리뷰의 고정 평가 결과 **62 → 76 → 83 → 89 → 91/100**. 1차는 새 Major로 폐기·복귀했고, 4차를 최종 채택했다. 관리자 프로토타입 범위의 디자인 승인 조건은 충족했으며 미해결 Critical/Major는 0건이다. **운영 납품 승인은 별도로 미승인**이다. 서버 인증·실계정·메일 발송과 실제 고객 인수 검수는 이번에 완료되지 않았다.

## 3. Iteration History

| 단계 | 실제 변경·주요 발견 | 점수 | 채택 |
|---|---|---:|---|
| Baseline | 낮은 대비·중복 프레임·상태/감사 혼용 | 62 | 기준 고정 |
| 1차 | 목록/상세 규칙 통일, 대비·밀도 개선. 모바일 아이콘 소실 발견 | 76 | **폐기 후 기준으로 복귀** |
| 2차 | 모바일 목록→검토 Dialog, 중첩 모달·초점 수명주기 수정 | 83 | 다음 개선 기준으로 채택 |
| 3차 | 집계·감사 표현·빈 상태·실패 복구. 별도 수락 검수에서 감사 payload와 저장값 검증 결함 추가 발견 | 89 | 개선 후보 채택, 납품 보류 |
| 4차 | 처리별 입력/기록 분리, 엄격 타입·중복 검사, 당일 집계·모바일 필터·읽기 실패 수정, 역할/운영 범위 우선 | **91** | **최종 채택** |

## 5. Implementation Report

수정한 제품 파일은 네 개다.

| 파일 | 변경 |
|---|---|
| `src/screens/Admin.jsx` | 공통 목록·필터·상세·확인 UI, 적응형 검토 패널, 의미가 정확한 상태·기록·복구 |
| `src/screens/admin.css` | 관리자 범위의 의미 색·간격·반경·타이포·밀도·초점·반응형 규칙 |
| `src/lib/accounts.js` | 원본 보존형 읽기 검증, 변경 충돌 방어, 처리별 감사 detail/notify 제한 |
| `src/lib/accounts.test.js` | 기존 목적을 보존하고 결함 회귀 케이스 추가, 최종 10개 |

새로 만든 파일은 `docs/design-harness/`의 원칙·루브릭·감사·반복 이력·보고서·증거와 `scripts/design-qa/{browser,capture,contrast,verify}.mjs`다. 의존성을 추가하지 않았다.

전역 컴포넌트·로그인·회원가입·운영 화면·공용 상태·빌드 설정은 수정하지 않았다. 기존 `App.jsx`의 관리자 진입 경로도 이번에는 그대로다. 관리자 CSS 변수는 `.dmin-admin`과 `.dmin-admin-dialog`에 제한했다. 기존 계정 레코드도 추가·삭제하지 않았다.

Figma는 지정 섹션의 기존 네 프레임 ID와 사용자가 정리한 가로 배치를 유지했다. 편집 가능한 텍스트·벡터·컴포넌트 인스턴스로 반영했으며 전체 화면 이미지를 레이어로 넣지 않았다. 원래 로고만 36×36 이미지다. 새 Figma 변수는 관리자 전용 컬렉션으로 생성해 이 섹션에만 바인딩했으며, 기존 변수나 다른 화면의 연결은 변경하지 않았다. [구조 기록](evidence/figma-structure.json), [전체 계정](evidence/figma-account-final.png), [섹션 전체](evidence/figma-section-final.png). 코드의 Pretendard는 유지했고 Figma는 사용 가능한 Noto Sans KR을 대체 글꼴로 사용했다.

## 6. Verification Report

- **빌드:** `npm run build` 성공. [최종 제품 코드 빌드 로그](evidence/build-final.log). 기존 대형 번들 경고는 유지했고 이를 이유로 의존성/설정을 변경하지 않았다.
- **단위:** `node --test src/lib/accounts.test.js` **10/10**. 선행 검토·팀장 승인, 상태 전이, 사유, 이력 detail/notify, 저장 실패·손상 원본, 다른 창 변경, 잘못된 역할·boolean·표시 필드·중복 ID 검사.
- **필수 브라우저:** `node scripts/design-qa/verify.mjs iteration-4` **18/18**. 키보드 Tab/Shift+Tab/Enter/Space/Escape, 중첩 모달 진입·복귀, 승인/반려/권한/활성 상태, 필터·빈 결과, 새로고침, 감사 집계, 저장 실패 입력 보존·재시도·손상 복구, 기존 두 역할 로그인·메뉴. [기록](evidence/iteration-4/verification.json).
- **시각:** 최종 23개 상태 PNG. 1920×1080, 1440×900, 1280×800, 768×1024, 390×844. 새로 반영한 Figma 네 프레임의 글자 잘림 없음, 이미지 전체 UI 평탄화 없음.
- **접근성 범위:** 실제 가시 DOM 텍스트 59개와 70개 표본에서 대비 실패 0, 최소 **5.33:1**, 12px 미만 0. 키보드 초점 진입·복귀도 별도로 검사했다. [대비 기록](evidence/iteration-4/contrast.json). 전체 WCAG 인증이나 스크린리더 발화 검증은 아니다.
- **오류:** 신규 런타임 오류 0. Baseline부터 있던 `/favicon.ico` 404는 캡처 JSON에 그대로 남겼고 범위 밖 파일을 수정하지 않았다.
- **범위 보존:** `package.json`, `bun.lock`, 기존 미추적 `package-lock.json`의 해시 동일. 로그인/공용 상태/기존 업무 파일 동일. [범위 기록](evidence/scope-integrity.json).

사용자의 “필수 테스트만” 지시 이후 이미 통과한 정상 기능을 반복하지 않았다. 제품 코드에 추가 변경이 없으므로 성공한 4차 빌드 로그를 재사용했다. 이후 수행한 확인은 새 Figma의 필수 구조·잘림 확인과 범위·데이터 보존 기록이다.

## 7. Remaining Defects

| 항목 | 상태 |
|---|---|
| 관리자 프로토타입 범위의 Critical/Major | **0건** |
| 빈 결과·읽기 실패의 ‘1’ 페이지 버튼 | Minor, 데이터 이동은 불가하며 번호 표시만 남음 |
| 모바일 행 초점선 일부 잘림 | Minor, 초점은 식별 가능하나 내부 테두리로 개선 여지 |
| 실제 인증·실계정 API·메일 발송 | 기존 미연동. 운영 권한 적용/실발송 완료로 주장하지 않음 |
| 실제 조직의 스케줄러 승인 정책·대규모 계정 | 미검증 |
| 스크린리더 음성 출력·전체 WCAG·전체 업무 회귀 | 미검증 |
| 고객 인수 검수 | 미실시 |

**최종 판정:** 관리자 프로토타입의 디자인·구현 승인 조건은 충족한다. 실제 운영 납품 승인은 미충족 상태로 명시한다. 이번 작업으로 새 서버나 실제 계정을 임의로 만들지 않았다.
