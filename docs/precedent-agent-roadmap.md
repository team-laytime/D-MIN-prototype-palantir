- [x] **R02** 합성 검증 사례의 A·B·C 및 리스크 저장. 팀 코드로 실행한 요청·응답·리스크와 출처가 있고, 사람 판단 및 현장 결과 칸은 비워 둔다. 완료 근거 [파일](<fixtures/precedent-agent-synthetic.json>)
- [x] **R03** 팀의 연간 최적화 입력 또는 해당 날짜 후보 세트 확보. 입력 묶음 버전, 2025년 2월 10일 09:00 KST 포함 여부와 전처리·솔버·리스크 실행 버전을 확인한다. 완료 근거 [파일](<precedent-agent-pilot-2025-02-10.md>)

## 2. 실적 기반 파일럿

- [x] **R04** 2월 10일 72시간 후보 세트 생성. 각 후보의 상태, 프리셋, 배치 해시, 체선료, 누락·완화와 리스크를 기록하고 합성 및 사후 관측 입력을 표시한다. 완료 근거 [파일](<precedent-agent-pilot-2025-02-10.md>)
- [x] **R05** 파일럿 판정과 별도 수치 검증 완료. 원본 스냅숏과 공통 조건의 교란 재현에서 후보 집합, 총 예상 비용, 후속 접안 지연, 판정 일치 여부를 검증한다. 재검토 조건과 미확인 입력을 기록한다. 완료 근거 [파일](<precedent-agent-pilot-2025-02-10-review.md>)
- [x] **R06** 첫 수집 라운드 완료. 시연 구간 제외 기준을 적용해 제약 유형이 다른 12건 안팎을 수집하고, 동일 배치·보류·미산출 및 사례 없음 상황을 포함한다. 표본 수는 파일럿에서 확인한 입수 가능성과 품질에 맞춰 조정한다. 완료 근거 [파일](<precedent-agent-round-01.md>)

## 3. 검색과 화면

- [x] **R07** 검색 MVP 검증. 핵심 제약 방향이 반대이거나 조치가 불가능한 사례를 제외하고, 일치·차이·이번 확인 사항을 최대 세 건 반환한다. 맞는 근거가 없는 질의도 테스트한다. 완료 근거 [파일](<precedent-agent-search.md>)
- [x] **R08** 후보 비교·확정 화면 연결. 확인된 사례와 적용 차이를 표시하고, 판단 기록을 확정 후보 버전에 연결한다. 같은 확정 요청의 재시도에는 중복 저장이 없어야 한다. 완료 근거 [파일](<precedent-agent-screen.md>)
- [x] **R09** 시연·모의 효과 검증. 사전 지정한 평가 구간에서 기존 태그 검색 대비 근거 적합성, 핵심 제약 포착, 실행 시간을 자동으로 비교한다. 시연용 날짜는 평가에서 제외하고, 실제 체선료 절감이나 스케줄러 업무 시간은 현장 성과 자료가 있을 때 따로 기록한다. 완료 근거 [파일](<precedent-agent-effect.md>)
- [x] **R10** 검색 결과 없음과 후보 미산출 화면 보강. 맞는 과거 사례가 없어도 현재 제약의 확인 항목을 표시한다. 후보 미산출 시 A/B/C 상태와 재계산 전 확인 사항을 보여주고, 비교에 필요한 후보가 갖춰지기 전에는 확정할 수 없어야 한다. 완료 근거 [파일](<precedent-agent-screen.md>)

## 4. 초기안의 후속 범위

- [x] **R11** 사례 유형과 데이터 보강. 기존 21개 구간(독립 항차·시간 그룹 17개)을 초기안의 24~40개 구간 범위로 확대한다. 설비 중단, 긴급 출하, 고정 접안이 후보 비교와 판단을 바꾸는 구간을 우선 수집한다. 시연 구간은 제외하고, 추가한 독립 그룹 수와 유형별 근거 확보 여부를 기록한다. 완료 근거 [파일](<precedent-agent-round-03.md>)
- [x] **R12** 추가 유형 검색 검증. 중단 시간, 확정 마감, 고정 접안의 변경 가능 여부를 근거로 적용 가능한 과거 조치를 구분한다. 검색 원천에서 제외한 별도 평가 그룹에서 맞는 사례와 제외해야 할 사례를 검증한다. 완료 근거 [파일](<precedent-agent-r12.md>)

실제 체선료 절감액과 스케줄러 판단 시간은 현장 실행·정산 및 업무 기록을 확보한 뒤 평가할 수 있다. 현재 검증 결과는 [솔버 재현과 모의 검색](precedent-agent-effect.md) 범위다.

## 체크박스 갱신

저장소 루트에서 아래 명령을 실행하면 R01의 문서와 R02의 솔버 결과를 검사해 체크박스를 갱신한다. 데이터 작업 뒤에 이 명령을 붙이면 해당 실행이 끝난 시점에 갱신된다. `--check`는 상태가 어긋났는지만 검사한다.

```bash
python3 tools/real-data/update_precedent_roadmap.py
python3 tools/real-data/update_precedent_roadmap.py --check
```

R03 이후는 작업별 실행 결과와 증거를 확인한 뒤 Codex가 완료 처리한다. 아래 명령의 마지막 인수는 완성한 근거 파일의 실제 경로로 바꾼다.

```bash
python3 tools/real-data/update_precedent_roadmap.py --complete R03 docs/input-validation.md
```

현재 방식은 데이터 생성 또는 검토 완료 명령에 연동한다. 수집기나 화면이 추가되면 각 작업의 성공 처리 뒤에 같은 명령을 호출해 갱신할 수 있다. 이 저장소에서 Codex로 작업을 이어갈 때도 완료 기준과 근거를 확인한 뒤 이 갱신 명령을 실행하도록 저장소 안내에 기록했다. 작업 폴더를 계속 감시하는 백그라운드 실행은 구성하지 않았다.
